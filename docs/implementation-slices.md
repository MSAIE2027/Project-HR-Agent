# TDD and Implementation Slices

Each slice starts at a public seam or a directly executable operator command. The project’s approved test seams are the public `/chat` response and public `RagIndex` behavior; protocol checks cross the MCP client/server boundary.

| Slice | Red / discovered failure | Green change | Evidence |
|---|---|---|---|
| S1 — Demo prompts match supported synthetic data | UI test found `E001` examples although only `E1001`–`E1008` exist; the “another state / six weeks” scenario did not use the international-work workflow. | Replaced the prompts with `Can E1001 work remotely overseas for 10 days?`; the ticket example now uses the implemented sensitive-case confirmation route. | `tests/test_app.py`; visible chips and evaluator lab in `app/static/index.html`. |
| S2 — Workflow tests reflect current acceptance | Legacy expectations exercised an absent employee and an unsupported PTO-ticket route rather than the documented international-work and sensitive-case workflows. | Replaced these expectations with an over-limit international request and a confirmation-gated sensitive case. | Public `/chat` tests cover expected status, exact tools, evidence, and no-production wording. |
| S3 — Embedding-provider test configuration | The embedding tests supplied `MSAIE_LLM_*`, so the code correctly tried the local Hugging Face path; the test failed to reach the mocked embedding endpoint. | Configured the tests with `MSAIE_EMBEDDING_PROVIDER`, `MSAIE_EMBEDDING_BASE_URL`, and `MSAIE_EMBEDDING_API_KEY`. | `tests/test_semantic_embeddings.py`; dense-provider and fallback cases pass without calling an external endpoint. |
| S4 — Direct script reproducibility | `python scripts/smoke_mcp.py` and `python scripts/build_index.py --help` failed to import root packages because Python placed `scripts/` rather than the project root on the import path. | Both scripts add their resolved project root before importing application packages. | Direct stdio smoke and `build_index.py --help` commands pass. |
| S5 — PTO draft wording | Browser rehearsal exposed duplicated wording (`PTO request request`) and inconsistent subject capitalization after the mock action was confirmed. | Added assertions at the public chat response seam, then normalized the purpose label and subject while preserving confirmation-gated mock-only behavior. | `tests/test_app.py`; `mcp_server/tools.py`; local browser rehearsal. |
| S6 — Latency evidence | The first request in the claimed warm sample included model/index initialization, while the percentile calculation omitted the maximum of 15 values. | Prime with one read-only request outside the sample; report its time separately; calculate p50/p95 using nearest rank and state the method. | `evaluation/run_evaluation.py`, `tests/test_evaluation.py`, `evaluation/results.md`. |
| S7 — Active conversation layout | Browser review showed the persistent examples panel pushed the live answer out of view. The `hidden` attribute also lost to the panel's explicit flex display. | Hide the examples after the first user prompt, add a matching `[hidden]` display rule, and restore the examples with New chat. | `app/static/index.html`; `tests/test_app.py`; desktop/mobile browser review. |
| S8 — Whole-system validation | Existing state lacked a current full-suite, complete golden-set artifact, and a maintained CI definition. | Ran all tests and the complete 25-case local golden set over in-process and stdio; added push/PR CI, evidence artifacts, and an opt-in tested-SHA Render deploy job. | `evidence/index.md`, both `evaluation/results*.json` reports, `.github/workflows/ci.yml`, ADR 0006. |
| S9 — Required final answer generation | The legacy flow called OpenRouter inside only one route; confirmation and other citation-bearing results could bypass it, and failure could expose the controlled draft. | Centralized composition after orchestration for every citation-bearing result; require the OpenRouter endpoint and try pinned Qwen, Nemotron Lightning, and Gemma free models before `openrouter/free`; return HTTP 503 if all routes fail or return invalid output. | Public `/chat` tests cover cited confirmation results and fail-closed errors; provider tests cover the ordered fallback chain, invalid-output failover, route enforcement, and safe status metadata. A real synthetic provider call is a separate local runtime check, never part of CI golden evaluation. |
| S10 — Reject exposed model reasoning | Output could preserve required numeric facts yet include process narration or reasoning-like text. | Strengthened the composer instruction and added a deterministic post-generation check for analysis headings/tags and common reasoning or request-restatement markers. Rejected text stays out of the API response; traces retain only a validation issue and model-attempt metadata. | A public `/chat` regression test supplies synthetic reasoning-like output that includes the required PTO number and asserts HTTP 503 without exposing that text. Current hosted acceptance evidence is maintained separately. |
| S11 — Bound model fallback time | Four sequential provider attempts at the previous timeout could consume most of the hosted request deadline before response validation. | Reduced the provider timeout default and hard cap to 12 seconds per route, bounding the four-route chain to 48 seconds before setup and retrieval. | Provider tests assert both the hard cap under a large override and the 12-second default. Hosted request acceptance is tracked in [`../deployed.md`](../deployed.md). |
| S12 — Preserve whole evidence chunks and reject incomplete model output | Public retrieval returned `content[:650] + …`, which could cut evidence in the middle of a word or sentence; provider output marked `finish_reason=length` could still pass answer validation. | Retrieval now passes complete 120-word chunks. OpenRouter output marked truncated or ending in an ellipsis is rejected and the next configured route is tried. The composer prompt prioritizes short, complete, non-repetitive wording. | Public `RagIndex` and provider regressions cover full chunk text and fallback after truncated completion. |
| S13 — Refuse multi-employee and medical-record requests | The orchestrator extracted only the first employee ID, so a request naming multiple IDs could silently appear to be a single-record request; medical-file wording and mixed ID/name comparisons also needed coverage. A medical-chart request combined with a PTO lookup could bypass the existing phrase check. | Requests referring to more than one synthetic employee (from explicit IDs or the fixture roster) are refused before MCP. Medical records, files, charts, and related phrasing are refused before lookup; the response directs leave documents to the confidential HR channel. | Public `/chat` tests assert no employee tool or LLM call occurs, including mixed ID/name and PTO-plus-medical-file/chart phrasing. |
| S14 — Make the SQLite index and response formatting visible | The browser displayed Markdown as raw text and provided no way to inspect document/chunk rows behind its SQLite vector index. | The browser safely renders common Markdown structures; the evaluator lab browses bounded document/chunk rows from read-only endpoints without exposing stored vectors or database paths. Repeatable chips cover multiple fixed synthetic employee scenarios. | Public UI/API and `RagIndex` regressions cover rendered feature presence, index routes, document/chunk listing, vector omission, and example prompts. |
| S15 — Verify the hosted demo through its public API | Hosted health alone could confirm configuration and MCP discovery without proving that the required LLM refinement, citations, privacy refusals, or confirmation gate work end to end. | Added a sanitized public-HTTP preflight for deep health, multi-employee and medical privacy refusals, remote-work guidance, and an unconfirmed PTO draft. A separate explicit flag exercises the fictional mock email action. | `scripts/smoke_hosted_demo.py`; CLI contract tests use a local fake HTTP server and never call Render or OpenRouter. Live acceptance remains separately gated by provider availability. |
| S16 — Reuse the hosted MCP process | The stdio app started and closed an MCP subprocess for every chat request. A request during MiniLM loading returned HTTP 502 near the Render service memory limit; the exact cause was not proven. | In stdio mode, FastAPI owns one official MCP session for its lifespan. Tool sequences are serialized; a failed operation makes the current request unavailable. Routine readiness reads cached MCP status without waiting on the session lock; explicit deep health performs live discovery. The local in-process default remains unchanged. | Public `/chat` coverage verifies one subprocess across normal requests and a safe response after simulated disconnect; readiness coverage verifies it does not wait on the MCP session. CI run `36321773923` passed and commit `400dad4` was deployed. The first hosted MiniLM load completed without a restart and readiness probes continued; memory peaked within 606,200 bytes of the service cap, then settled at 493,432,830 bytes. Hosted answer generation remains blocked by OpenRouter's free-model daily limit. |
