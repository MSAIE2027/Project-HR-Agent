# TDD and Implementation Slices

Each slice starts at a public seam or a directly executable operator command. The project’s approved test seams are the public `/chat` response and public `RagIndex` behavior; protocol checks cross the MCP client/server boundary.

| Slice | Red / discovered failure | Green change | Evidence |
|---|---|---|---|
| S1 — Demo prompts match supported synthetic data | UI test found `E001` examples although only `E1001`–`E1008` exist; the “another state / six weeks” scenario did not use the international-work workflow. | Replaced the prompts with `Can E1001 work remotely overseas for 10 days?`; the ticket example now uses the implemented sensitive-case confirmation route. | `tests/test_app.py`; visible chips and evaluator lab in `app/static/index.html`. |
| S2 — Workflow tests reflect current acceptance | Legacy expectations exercised an absent employee and an unsupported PTO-ticket route rather than the documented international-work and sensitive-case workflows. | Replaced these expectations with an over-limit international request and a confirmation-gated sensitive case. | Public `/chat` tests cover expected status, exact tools, evidence, and no-production wording. |

Hosted post-deploy request evidence will show whether the full path now returns inside the edge deadline. |

The public evaluation summary counts only workflow-category cases and exposes the denominator.
