# Security control map

**Scope:** public, synthetic-data course demo only. This note maps selected implementation evidence to NIST and OWASP references; it is not a security assessment, certification, or claim of conformance. NIST describes the AI RMF functions as a risk-management structure, not a checklist. The mapping below records relevant design evidence and gaps for this application.

## Control and risk mapping

| Reference | Current implementation evidence | Residual risk and boundary |
|---|---|---|
| **NIST AI RMF / GenAI Profile — Govern, Map, Measure, Manage; GV-1.3-002, MP-2.3-005, MS-2.5-003, MG-1.3-002** ([AI RMF Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/), [NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)) | The intended-use boundary is written down as synthetic HR data and local mock actions. CI includes deterministic workflow, safety, retrieval, and citation checks. This is evidence of documented scope and selected evaluation activities, not evidence that an organization-wide NIST risk-management process is in place. | The evals do not establish semantic truth of every generated answer. Hosted live answer acceptance is currently blocked by OpenRouter quota; hosted cold-start timing is unmeasured. There is no production HR oversight, incident response, or ongoing monitoring program represented by this demo. |
| **Identity and record access — NIST SP 800-53 AC-3 Access Enforcement / AC-6 Least Privilege** ([SP 800-53 Rev. 5](https://csrc.nist.gov/CSRC/media/Projects/risk-management/800-53%20Downloads/800-53r5/SP_800-53_v5_1-derived-OSCAL.pdf)) | Authentication and role authorization are explicitly out of scope. An employee ID identifies a fixture; it is not checked against a user principal. Requests mentioning multiple employees are refused before MCP access, but a single fixture ID can be queried by any visitor. | **No real employee information may be entered.** This demo does not provide self-service access control. A production service would need authenticated principals and server-side, per-record authorization on every data and action path; a UI session or employee ID is not authorization. |
| **Prompt injection — OWASP LLM01:2025; NIST GenAI Profile adversarial manipulation risks** ([OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/), [NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)) | A deterministic orchestrator checks a small set of direct injection patterns before tool access. The answer prompt marks retrieved passages as untrusted data. The LLM composes answers but does not select tools or set workflow decisions. | The refusal check is pattern-based and does not comprehensively detect paraphrases, obfuscation, multilingual attacks, or indirect injection in retrieved content. Prompt wording and RAG do not eliminate injection risk; do not describe this as injection-proof. |
| **Sensitive information — OWASP LLM02:2025; NIST GenAI Profile Data Privacy risk** ([OWASP LLM02](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/), [NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)) | The application uses synthetic fixtures, refuses medical-record requests and multi-employee requests before lookup, keeps provider keys in environment configuration, and does not return raw provider error bodies. For citation-bearing answers it sends the controlled draft, retrieved passages, and structured fixture facts to OpenRouter or the configured OpenCode Zen fallback. The current OpenCode Zen free-model set is allow-listed in code. | `mcp_client/client.py` puts tool arguments and results in the API/UI trace; values are only truncated at 1,200 serialized characters, not redacted. OpenCode documents temporary free-model offers and model-specific data-use exceptions; see its [current pricing and privacy terms](https://opencode.ai/docs/en/zen/). This is acceptable only for the documented synthetic demo boundary. Do not put real employee data or secrets in prompts. Before any real-data use, assess both providers' terms and minimize/redact data in prompts, traces, logs, and errors. |
| **Tool agency and action approval — OWASP LLM06:2025 Excessive Agency; NIST SP 800-53 AC-6** ([OWASP LLM06](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/), [SP 800-53 Rev. 5](https://csrc.nist.gov/CSRC/media/Projects/risk-management/800-53%20Downloads/800-53r5/SP_800-53_v5_1-derived-OSCAL.pdf)) | Tool routing is deterministic and bounded to registered MCP functions. Email/ticket operations create local fictional records only, and the tools reject calls unless `confirmed=true`; the UI presents a confirmation step. The LLM cannot authorize an action. | `confirm_action` is a Boolean in the public `/chat` request, and the orchestrator passes it through; it is not bound to an authenticated user, a pending action, or a server-issued confirmation token. That is a demo interaction gate, not production authorization. Any future real action needs server-side principal-bound authorization and confirmation, narrowly scoped permissions, and an auditable action lifecycle. |
| **Generated-output handling and confabulation — OWASP LLM05:2025 Improper Output Handling; NIST GenAI Profile Confabulation risk** ([OWASP LLM05](https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/), [NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)) | Citation-bearing responses try OpenRouter, then the configured OpenCode Zen fallback. Both pass deterministic status, numeric, safety-language, reasoning-leakage, and truncation checks. If live generation fails, versioned SQLite templates can format fresh facts and citations for supported read-only workflows; the database stores no personalized answers. Unsupported, unsafe, confirmation-gated, and template-miss cases return HTTP 503 without the draft. | These string and numeric checks do not prove semantic entailment or complete formatting safety. The evaluator's control-flow/citation measures are not a human judgment of live model groundedness. Keep the current fail-closed behavior; do not present the model as a decision-maker or its checks as a guarantee of correctness. |

## Practical operating boundary

- Use synthetic demo prompts and fixture IDs only. The public app has no authentication or role-based access checks.
- Do not paste medical records, employee PII, credentials, or confidential company content. Trace truncation is not data redaction.
- Treat confirmation as a visible demo pause for local mock actions. It does not represent identity verification or authorization for real actions.
- Treat prompt-injection refusal and response validation as narrow, testable safeguards with known limits, not complete prevention.
- OpenRouter is the primary cited-answer composer; OpenCode Zen is a configured live fallback, followed by narrow SQLite formatting templates for fresh supported cases. No template applies to actions, unsafe requests, or unsupported workflows. Refusals before retrieval do not require model generation.
