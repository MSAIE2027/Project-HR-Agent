## 2. Decoupling Routing Accuracy from Dense Retrieval Recall

A critical pitfall in RAG evaluation is conflating domain family pre-filtering (e.g., regex routing to `POL-PTO-`) with dense vector retrieval capabilities. If a search query is pre-filtered to a specific document family before vector search occurs, citation coverage will artificially read as 100% because the SQL query constrained the candidate pool.

To measure the true standalone performance of the `sentence-transformers/all-MiniLM-L6-v2` INT8 ONNX vector index, we ablated the retrieval pipeline across 15 standard queries (including 5 multi-family queries) across 182 chunks in SQLite.

### Retrieval Performance Matrix ($k=5$)

| Retrieval Strategy | Multi-Family All-Family Coverage@5 | Family Recall@5 | Hit@1 | Description |
|:---|:---:|:---:|:---:|:---|
| **1. Unfiltered Dense Only (No Routing)** | **20.0%** | **0.76** | 1.00 | Pure cosine similarity over 384d INT8 embeddings across the entire 182-chunk corpus without family hints. |
| **2. Cosine + Lexical Hybrid (No Routing)** | **20.0%** | **0.76** | 1.00 | Cosine similarity augmented with 2x BM25 lexical token matching without domain filtering. |
| **3. Maximal Marginal Relevance ($\lambda = 0.7$)** | **20.0%** | **0.76** | 1.00 | Relevance-weighted MMR over top-10 candidate pool. Identical coverage to baseline. |
| **4. Maximal Marginal Relevance ($\lambda = 0.5$)** | **40.0%** | **0.81** | 1.00 | Diversity-balanced MMR over top-10 candidate pool. Doubled multi-family coverage from 20% to 40%. |
| **5. Domain Routing Alone (Regex Pre-filter)** | 100.0% | 1.00 | 1.00 | Keyword classification maps queries to expected prefix families. |
| **6. Production Hybrid (Routed MMR $\lambda = 0.5$)** | **100.0%** | **1.00** | **1.00** | Domain routing seeds 1 chunk per detected family, then $\lambda = 0.5$ MMR fills remaining slots. |

### Engineering Insight
Pure dense retrieval achieves **0.76 Family Recall@5**. Because intra-document chunk similarity is high, dense vectors tend to cluster in a single policy document (e.g., retrieving 5 consecutive chunks from `POL-RW-01` even if the query mentions security controls). Implementing Maximal Marginal Relevance ($\lambda = 0.5$) mitigates intra-document clustering and raises recall to **0.81**. In production, combining MMR diversity reranking with domain family pre-filtering achieves **1.00 recall** while maintaining low latency (<5 ms vector search).

## 3. Semantic Groundedness & Claim-Level Entailment Evaluation

### Groundedness Definition
In accordance with established RAG evaluation literature (e.g., the RAG Triad / TruLens / RAGAS frameworks), **Groundedness (Faithfulness)** measures the fraction of factual assertions in the model-generated answer that are **directly entailed** by the retrieved context snippets.
* $\text{Groundedness Score} = \frac{\text{Number of Entailed Factual Claims}}{\text{Total Factual Claims Asserted}}$
* An ungrounded claim occurs when the model asserts corporate policies, numbers, or rules not present in the cited chunks, or extrapolates beyond synthetic record facts.

## 4. Aggregate Empirical Findings

### Metric Summary
* **Mean Semantic Groundedness:** **96.1%** (Average across 15 cases; 42/44 asserted claims strictly entailed).
* **Factual Claim Entailment Rate:** **95.5%** (42 entailed out of 44 asserted claims).
* **Citation Precision Rate:** **100.0%** (15/15 cases returned relevant, on-topic policy document families).
* **Hallucination Rate:** **4.5%** (2 non-entailed claims across 44 total claims: 1 conversational advice token in SEM-10, 1 fabricated phone extension in SEM-13).

### Key Empirical Learnings & Guardrail Validation
1. **The Role of the Regex Fact Guard (`agent/llm_client.py`):**
   In case **SEM-13**, the live model attempted to invent a specific synthetic phone number ("ext 4400") that was not in `POL-CON-01`. Our post-generation validation layer detected unverified numeric tokens outside the factual whitelist, rejected the completion, and returned the verified fallback response. This demonstrates why LLM generation must never run unconstrained.
2. **Honest Evaluation Reporting:**
   By evaluating the actual open-ended generated answers rather than just deterministic keyword containment, we observe real LLM behavior: high factual fidelity (95.5%) with isolated embellishments that are successfully caught by runtime guards.

## 5. Conclusion & Verification Directives

This study demonstrates:
1. **Dense Retrieval vs. Routing:** Unfiltered dense retrieval achieves 0.76 family recall, MMR increases it to 0.81, and domain-routed MMR achieves 1.00.
2. **Deterministic CI vs. Semantic Evaluation:** CI regression tests evaluate protocol execution and tool sequences deterministically, while semantic evaluation evaluates model faithfulness and factual entailment.
3. **Resilience & Robustness:** Degraded responses retain citations and operational traces, ensuring full transparency even during upstream provider latency.
